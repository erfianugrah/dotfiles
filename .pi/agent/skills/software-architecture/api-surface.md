# software-architecture: API surface

Supporting reference for the `software-architecture` skill. The REST + WebSocket conventions: route shape, request IDs, idempotency keys, and the WS event envelope with seq-based replay.

## API surface - REST + WS pattern

REST for request/response. WebSocket for live updates. Both share correlation IDs.

```
GET  /api/health         { "ok": true, ... }
GET  /healthz            "ok"   (probe; unauthenticated)
GET  /metrics            Prometheus exposition

GET  /api/me             current principal
POST /api/<resource>     create
GET  /api/<resource>/:id read
POST /api/<resource>/:id/<action>  state transitions

WS   /ws/<topic>         live events; supports ?since=N replay
```

### Conventions

- **All requests carry an `X-Request-ID`**, generated by middleware if absent. Echo it in the response header and include `rid=<id>` in every log line for that request. Makes cross-process tracing free.
- **REST routes use plural resource names** (`/api/runs`, not `/api/run`).
- **State transitions are POSTs to a verb endpoint** (`POST /api/runs/{id}/abandon`), not PATCH with a magic field. Verbs read better and are harder to misuse.
- **204 No Content for accepted-but-no-body responses** (DELETE, idempotent state changes). 202 only when truly async.
- **Idempotency keys for any POST that could be retried**: header `Idempotency-Key: <uuid>`, server stores result for 24h keyed by `(principal, key)`. Especially for "create resource" and "trigger action" endpoints.

### WS event envelope

Wrap every WS message in a consistent envelope. Required for sane client-side dispatching:

```json
{
  "type": "match.event",
  "payload": { ... },
  "ts": 1700000000123,
  "seq": 42
}
```

- **`type`**: dot-separated `<context>.<event>`. Lowercase, no plurals.
- **`payload`**: event-specific. Type the JSON via a tagged union on the client.
- **`ts`**: server-side ms epoch.
- **`seq`**: monotonic per-stream. Critical for replay/reconnect - client tracks highest seen `seq`, reconnects with `?since=<seq>`, server replays everything after.

This eliminates a class of UX bugs around lost/duplicated WS messages on network blips. Worth the few extra bytes per message.
